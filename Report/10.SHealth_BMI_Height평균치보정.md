## 3. 보정 규칙 (weight=0 대칭)

| 항목 | 규칙 |
|------|------|
| 조건 | `height == 0.0` (`kMissingHeight`) |
| 대상 연령대 | `[a, a+10)`, a ∈ {20, 30, 40, 50, 60, 70} |
| 보정값 | 동 연령대 내 `height ≠ 0` 레코드의 **평균 키(cm)** |
| 예외 | 유효 height 0건 → 보정 스킵 (`validHeightCount == 0`) |
| 순서 | `imputeMissingWeightsByAgeBand()` **후** `imputeMissingHeightsByAgeBand()` **후** `computeAllBmis()` |

### 구현 위치

| 메서드 | 책임 |
|--------|------|
| `imputeMissingHeightsForBand` | 연령대별 평균 계산·height=0 대입 |
| `imputeMissingHeightsByAgeBand` | 6개 연령대 순회 |
| `calculateBmi` | 파이프라인에서 height 보정 단계 호출 (F1에서 연결) |

F3에서는 **로직 신규 작성 없음** — F1 SRP 단계에서 구현된 보정을 §5 #26·#29 TC로 명시 검증.

## 4. 신규 테스트 시나리오

### `ImputeHeight_ZeroInBand_UsesAverageHeight` (§5 #26)

| Given | When | Then |
|-------|------|------|
| 20대: 170cm 2명, height=0 1명(70kg) | `calculateBmi` | 평균 170cm 보정 → 3명 BMI≈24.22 → 과체중(300) 100% |

### `CalculateBmi_HeightZeroBeforeImpute_DivisionRisk` (§5 #29)

| Given | When | Then |
|-------|------|------|
| 20대: height=0(70kg) + 170cm(60kg) | `calculateBmi` | 크래시 없음, 과체중·정상 각 50% |

height 보정이 BMI 계산 **전**에 실행되므로, 동 연령대 유효 키가 있으면 `height=0`으로 인한 나눗셈 위험을 회피한다.
