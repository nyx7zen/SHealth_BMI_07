## 3. 핵심 결과 요약

### 3.1 SRP — `calculateBmi`가 담당하는 5가지 책임

1. CSV 파일 I/O  
2. 파싱·parallel array 저장  
3. `weight==0` 연령대 평균 보정  
4. BMI 산출  
5. 연령대별 4분류 집계·24개 비율 멤버 저장  

→ 단일 메서드(~103줄)에 집중된 **God Method** (Long Method).

### 3.2 OCP — 확장 시 수정 지점

| 신규 요구 (README 4단계) | 예상 수정 위치 |
|--------------------------|----------------|
| height=0 보정 | 보정 루프(`SHealth.cpp` L28–48) 인접 |
| 정상 BMI 목록 / 전체 범주 비율 | `calculateBmi` 또는 신규 순회 |
| 연령대 80대 추가 | 루프 상한, 멤버 4개, `getBmiRatio` 분기 4개 (**최소 3곳**) |

`getBmiRatio`의 **24-way if-else**는 age×type 조합마다 분기 추가만 가능해 OCP 위반이 크다.

### 3.3 스펙 vs 레거시 (우선순위 1 이슈)

| 이슈 | README | 레거시 |
|------|--------|--------|
| 비만 경계 | BMI **≥** 25 | `bmis[i] > 25` (L71) → **BMI=25 미집계** |
| 0 나눗셈 | — | `sum/ageCount` (L44), `*100/sum` (L77–105) |
| 테스트 | TDD 필수 | `SHealthBMITest.cpp` `FAIL()` only |

### 3.4 Code Smell Top 5

| 스멜 | 위치 | 개선 방향 |
|------|------|-----------|
| God Method | `calculateBmi` | 4단계 함수 추출 + Facade |
| Duplicated Code | 연령대 루프 3회, `a==20…70`, `getBmiRatio` 24분기 | `std::array` 2차원 테이블 |
| Magic Number | 18.5/23/25, 20~70, 100~400, 10000 | `constexpr`, `enum class` |
| Data Clumps | 4 parallel array + 24 `double` | `HealthRecord`, `AgeGroupStats` |
| 조건문 복잡도 | BMI 분류 L65–73 | `classifyBmi()` 단일화 |

### 3.5 C++17 개선 1순위 권장

**테이블 기반 집계·조회** (`std::array<std::array<double,4>,6>` 등)

- 24개 멤버 + 24-way 분기를 한 구조로 통합  
- `enum class BmiCategory` / `AgeBand`와 결합 시 매직 type 코드 제거  
- 전략 패턴보다 diff가 작고, 테스트(비율 합 ≈ 100%)로 검증 용이
