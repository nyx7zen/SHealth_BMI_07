Gilded Rose의 `updateQuality()`에 해당하는 핵심 로직은 **`SHealth::calculateBmi()`** (파일 I/O·보정·BMI·연령대 통계)와 **`SHealth::getBmiRatio()`** (연령대×분류 조회)입니다.

[T] 위 두 메서드 및 직접 연관된 private 멤버·`split()`을 **SOLID / Code Smell** 관점에서 분석해줘.

1. **SRP / OCP 위반 지점과 근거**  
   - `calculateBmi`가 담당하는 책임 나열 (CSV I/O, 파싱, weight=0 보정, BMI 산출, 연령대 집계·저장)  
   - 신규 요구(README 4단계: height=0 보정, 정상 BMI 목록, 전체 범주 비율 등) 추가 시 **어디를 수정해야 하는지** — OCP 관점  
   - `getBmiRatio`의 age×type if-else 사다리가 확장에 취약한 이유  

2. **Magic Number 상수화 필요성**  
   - BMI 임계값: `18.5`, `23`, `25`  
   - 연령대: `20`, `30`, … `70`, 구간 폭 `10`  
   - type 코드: `100`, `200`, `300`, `400`  
   - 기타: `100.0`(cm→m), `100`(백분율), `10000`(배열 상한), `0.0`(결측 체중), CSV 컬럼 인덱스 `1`/`2`/`3`  
   - 각각 **의미·변경 시 영향·상수화 제안 이름** (`constexpr`, `enum class` 등)

3. **Code Smell**  
   - **Long Method / God Method**: `calculateBmi` (~100줄, 4단계 파이프라인)  
   - **Duplicated Code**: 연령대 루프·`a==20/30/…` 분기·`getBmiRatio` 24-way 분기  
   - **조건문 복잡도**: BMI 분류 `if-else` (스펙 vs 레거시: `> 25` vs `≥ 25`, BMI=25 미분류)  
   - **Data Clumps**: `ages`/`weights`/`heights`/`bmis` + 24개 비율 `double` 멤버  
   - **기타**: 0 나눗셈(`ageCount`, `sum`), `count` 상한 미검증, `stoi`/`stod` 예외 미처리, 테스트 부재(`FAIL()`)

4. **C++17 스타일 개선 방향** (실행 코드 제안은 간략히, 설계 수준으로)  
   - **전략 패턴**: BMI 분류 규칙을 `BmiClassifier` / `std::function` 또는 policy 클래스로 분리  
   - **테이블 기반**: `std::array` / `std::map` / `(ageClass, BmiCategory) → ratio` 2차원 구조로 `getBmiRatio` 단순화  
   - **`std::variant` / `enum class`**: `BmiCategory`, `AgeBand`로 type `100~400` 매직 넘버 대체  
   - **구조체 응집**: `HealthRecord`, `AgeGroupStats` — parallel array 제거  
   - **Facade**: `SHealth`가 기존 공개 API 유지하며 내부 서비스 위임 (`CsvReader`, `ImputationService` 등 — `Report/0` 제안 구조 참고)  
   - 과도한 템플릿 메타프로그래밍· premature abstraction 은 지양

5. **리팩토링 우선순위 (1~5)**  
   - 각 항목에 **이유**(버그·회귀·확장성·가독성·테스트 용이성) 명시  
   - **테스트 Green 선행** (`tasks/0.setting.md` 규칙) — 현재 `SHealthBMITest.cpp`는 `FAIL()`만 있음을 반영

### [T] 섹션별 분석 깊이

#### SRP / OCP

- Gilded Rose `updateQuality`의 “아이템 타입별 분기 추가 = 함수 수정”에 대응:  
  - BMI **4분류 규칙** 변경 → `calculateBmi` 내부 분기  
  - **연령대 추가**(예: 80대) → 루프 상한·`getBmiRatio`·멤버 변수 24개 패턴 전부 수정 필요 → OCP 위반으로 기술  
- README 4단계 기능을 **기존 메서드에 누적**할 때의 결합도를 명시

#### Magic Number

| Gilded Rose (참고) | SHealth BMI |
|--------------------|-------------|
| quality `0`, `50` | BMI `18.5`, `23`, `25` |
| `sellIn` `0`, `-1` | 연령 `19`/`20`, `29`/`30`, 구간 `[a,a+10)` |
| `11`, `6` (Backstage 등) | type `100`~`400`, 연령 `20`~`70` step `10` |
| — | `10000`, `100.0`, `100`(%) |

#### Code Smell — 조건문 복잡도

다음 레거시 분기를 **표·설명에 반드시** 언급:

```cpp
// SHealth.cpp — 분류 (스펙과 대조)
if (bmis[i] <= 18.5) ...
else if (bmis[i] > 18.5 && bmis[i] < 23) ...
else if (bmis[i] >= 23 && bmis[i] < 25) ...
else if (bmis[i] > 25) ...   // README: ≥ 25
```

- BMI = `23.0`, `25.0` 경계에서의 집계 누락·오분류 리스크

#### C++17 개선 — 선택 가이드

| 패턴 | 적합한 SHealth 영역 | 비고 |
|------|---------------------|------|
| 테이블/맵 | `getBmiRatio`, 연령대별 4비율 저장 | 우선 적용 권장 |
| `enum class` | `BmiCategory`, `AgeBand` | type 100~400 대체 |
| 전략 | BMI 분류·향후 height 보정 규칙 | weight/height 보정 대칭 확장 시 |
| `variant` | 레코드 상태(결측/정상) | 선택; 과도한 사용 지양 |
| Facade `SHealth` | 공개 API 유지 | 리팩토링 후 호환 |

### 산출물 품질 기준

- 표의 “위반 원칙/스멜” 열: SOLID 항목(SRP, OCP, …) 또는 Martin Fowler 스멜 명칭 병기  
- “영향”: 런타임 버그 / 유지보수 / 테스트 불가 / 확장 비용 중 구체적으로
