[C] 제약  
- **공개 API 시그니처 유지**: `int calculateBmi(const std::string& filename)`, `double getBmiRatio(int ageClass, int type)` — 반환 의미·호출 규약 변경 금지 (`SHealthBMI.cpp`·테스트와 동기화 필요 시 본문에 명시만).  
- **도메인 규칙 고정** (`README.md` / `docs/requirements_analysis.md`): BMI 임계값 18.5 / 23 / 25, 연령대 `[20,30,…,70)` 구간 `[a,a+10)`, type 코드 100/200/300/400, `shealth.dat` CSV 포맷(`id,age,weight,height`) 변경 금지.  
- **테스트 Green에서만 진행**: 각 단계(커밋)마다 `cmake --build` && `ctest` 통과 후 다음 단계. Red 상태에서 리팩토링 확대 금지.  
- **전역 변수 추가 금지**; premature abstraction(과도한 템플릿·variant 남용) 지양.  
- `docs/code_quality_report.md` 우선순위·스멜 진단을 계획의 근거로 인용.

[T] `calculateBmi()`·`getBmiRatio()` 리팩토링 계획을 **단계별·커밋 단위**로 제안해줘. (Gilded Rose의 `updateQuality()`에 대응하는 핵심 로직.)

1. **조건 분기 축소 / 중복 제거** (커밋 단위로 쪼개기)  
   - BMI 분류 `if-else` (스펙: BMI≥25 비만 vs 레거시 `> 25`)  
   - 연령대 `[a,a+10)` 필터 3회 반복 (보정·집계·저장)  
   - `a==20/30/…/70` 저장 분기 6×4줄  
   - `getBmiRatio` 24-way if-else 사다리  
   - 각 단계: **작업명 | 변경 파일 | 예상 diff 규모 | 선행 테스트** | **커밋 메시지 예시**

2. **타입 / 정책 분리** (전략 패턴 / 테이블 기반 / 함수 분해)  
   - `classifyBmi(double) -> BmiCategory` (경계 일원화)  
   - `std::array` 또는 `AgeGroupStats` 테이블로 집계·조회 통합 (`code_quality_report` 1순위 권장)  
   - 선택: `BmiClassifier` policy, `CsvReader` / `ImputationService` — **Facade `SHealth`가 공개 API 유지**  
   - README 4단계(height=0 보정·정상 BMI 목록·전체 비율)는 **신규 public 메서드**로 분리 — God Method 누적 금지

3. **매직 넘버 상수화 & C++17 스타일**  
   - `constexpr` BMI 임계값, `enum class BmiCategory` / `AgeBand`, `kPercentFactor`, `kCmPerMeter` 등  
   - parallel array → `std::vector<HealthRecord>` (테스트 Green·동작 동일 전제)  
   - `split` → CSV 파싱 책임 분리 (낮은 우선순위)

4. **단계 순서** — 아래 순서를 따르거나, 근거와 함께 조정안 제시:  
   `테스트 스위트(Green) → 스펙 버그 수정(BMI=25) → 상수화 → 함수 추출 → 테이블화 → SRP·신규 API`

5. **Phase D — SRP·README 4단계 확장** — 신규 메서드 목록·God Method 방지 원칙  
6. **리스크·회귀 포인트** — BMI 경계, ageCount/sum=0, `count`>10000  
7. **전체 완료 체크리스트** — `docs/requirements_analysis.md` §5 시나리오 1~30 중 최소 커버리지 표

### 산출물 품질 기준

- 각 단계는 **단독으로 빌드·테스트 통과** 가능해야 함 (중간 단계도 Green).  
- “함수 추출” 단계는 **동작 동일** refactor만; 스펙 변경은 **전용 커밋** + TC 명시.  
- `docs/code_quality_report.md` 우선순위 1~5와 **단계 번호 매핑** (표 각주 또는 별도 열).  
- README 4단계 기능은 **별도 Phase D** — `calculateBmi`에 누적하지 않는다고 명시.  
- 커밋 메시지는 **영문 또는 한글** 일관되게, 동사 원형 (`test:`, `fix:`, `refactor:`).

- 본 프롬프트는 **계획 문서만** 산출 — 실제 `SHealth.cpp` 수정은 사용자가 단계별로 요청할 때 수행.
